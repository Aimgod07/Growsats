# Bulk announcements

In PMS, open **Notifications → Send a broadcast**. Enter a title, message and destination, review the preview, then select **Send to all users**.

- Every non-banned player receives one inbox entry. Existing players only; new accounts do not receive past broadcasts automatically.
- Push is sent only to registered, opted-in devices. Web subscribers currently enable this through the notification/reminder preference.
- The composer retains its request ID on a failed request, so retrying the unchanged message does not duplicate inbox records or delivery jobs.
- Delivery runs in small batches, with a scheduled retry worker. Temporary network errors are retried up to three attempts. Stale jobs expire after 24 hours.
- Counts distinguish pending, accepted, failed and skipped devices. Accepted means the push service accepted the message, not that it was displayed or read. OS notification tags collapse duplicate transport retries.
- Delivery checks current ownership and subscription before sending. Revoked devices and banned players are skipped. Expired push tokens are removed.
- Sending a real announcement is a PMS action. Development verification uses isolated databases and does not contact players.

The dedicated sender credential is stored only in the existing Cloudflare Worker secret `FCM_SERVICE_ACCOUNT`. The Firebase-enabled debug APK built successfully.

Install the updated APK and select **Notifications → Game announcements → Enable announcements**. Actual device delivery still needs verification on an opted-in phone.

For future replacement builds or credential rotation:

1. Create a Firebase project and register Android application **com.grosats.Growgames**.
2. Put its `google-services.json` at `android/app/google-services.json`.
3. Enable Firebase Cloud Messaging HTTP v1. Create a service account with permission to send FCM messages.
4. In the backend project, store the service account JSON as the Cloudflare Worker secret `FCM_SERVICE_ACCOUNT`. Never put it in the frontend, PMS, public folder, or Git.
5. Rebuild the frontend, run Capacitor sync, and rebuild/install Android. The build detects the Firebase configuration file. Players opt into announcements in Notifications.

Do not rerun the provisioning script routinely: it creates a new sender key. Rotate credentials deliberately and revoke the old key after verifying the replacement.

Official references: https://capacitorjs.com/docs/guides/push-notifications-firebase and https://firebase.google.com/docs/cloud-messaging/send/v1-api.

## Gro Games covers and limits

PMS **Gro Games** controls visibility and card count independently from provider games and the featured carousel. Zero means all. Publish changes to apply.

Bundled cover assets are generated by `node scripts/build-game-covers.mjs` from the manifest. Provider covers are generated from game identity, category and title. Animations run only for visible covers, pause when hidden, and respect reduced-motion preferences. `/cover-preview.html` is a local Vite gallery and is not included in the production build.
